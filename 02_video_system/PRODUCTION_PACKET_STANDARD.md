# Production Packet Standard

**Status:** Canonical portfolio-wide standard  
**Purpose:** Translate an approved script into clear visual direction so an editor can execute the video without reinventing the editorial concept.

---

## 1. Role

The production packet is the bridge between editorial intelligence and human visual production.

A strong packet reduces:

- editor guesswork
- unnecessary revisions
- inconsistent visual interpretation
- dependence on expensive creative producers
- generic filler footage

It should not eliminate editor judgment.

It should ensure the editor spends judgment on execution rather than discovering what the video means.

---

## Portfolio-Wide Editor Standard

Every production packet must be interpreted alongside:

- `06_production_system/EDITOR_CREATIVE_STANDARD.md`
- `06_production_system/VISUAL_QUALITY_STANDARD.md`

The production packet defines the intended editorial and visual direction for a specific video.

Those portfolio standards define the editor's creative discretion and the minimum visual quality threshold.

Where a packet contains a weak `PREFERRED` treatment, the editor is expected to improve it rather than execute it mechanically.

---

## 2. Required Inputs

Before the packet is created, the system should have:

- approved script
- source log
- channel visual style
- channel production standard
- current packaging direction
- narration plan
- available source assets
- known rights constraints

---

## 3. Required Header

Include:

- video ID
- working/final title
- target runtime
- channel
- version
- script version
- visual style link or reference
- production priority
- special risks

---

## 4. Section-Level Direction

For each major section include:

### Narration Range
Identify the relevant script block.

### Visual Objective
What should the viewer understand or feel visually?

### Preferred Visual Treatment
Examples:

- archival footage
- stock footage
- map
- chart
- screenshot
- document
- product footage
- typography
- diagram
- animation
- still photography
- AI-generated illustrative visual if allowed

### Specific Asset Suggestions
Where useful, identify candidate assets or sources.

### Graphics
Define required charts, maps, labels, arrows, callouts, or diagrams.

### On-Screen Text
Specify only where it adds value.

### Pacing Note
Fast, patient, reveal, montage, hold, etc.

### Sound / Music Note
Only where materially useful.

### Evidence Note
Where factual visuals require source integrity.

### Editor Freedom
Identify where the editor may improvise.

---

## 5. Shot-Level Detail

Not every sentence requires a shot instruction.

Use shot-level specificity when:

- a visual is essential to understanding
- a factual graphic must be accurate
- a reveal depends on timing
- the asset is hard to source
- the channel style requires a precise sequence

Avoid producing a 1:1 sentence-to-shot spreadsheet that destroys editorial flexibility without adding value.

---

## 6. Visual Hierarchy

The packet should distinguish:

### Required
Must be shown or communicated visually.

### Preferred
Best current direction.

### Optional
Useful possibilities.

### Avoid
Treatments that would mislead, bore, or violate the visual standard.

---

## 7. Asset Guidance

For important assets, include:

- source
- rights status if known
- timestamp/page where relevant
- whether alteration is allowed
- whether attribution is needed
- whether the asset is evidence or illustration

---

## 8. Graphics Instructions

For each nontrivial graphic, specify:

- purpose
- data
- labels
- units
- source
- desired insight
- what not to imply

Do not ask editors to infer data from prose.

---

## 9. Narration Production

For synthetic-narration channels, the production packet should assume narration is generated by the editor during production unless the channel standard explicitly says otherwise.

Identify:

- locked channel voice profile
- approved provider / access method
- baseline model or settings where relevant
- pronunciation notes
- pacing concerns
- intentional pauses or reveal beats

Do **not** require a final narration audio filename before production begins.

The editor may iterate delivery against picture but may not change approved script wording or substitute a different narrator identity without approval.

---

## 10. Packaging Relationship

Where the thumbnail or title establishes a visual motif, the production packet should consider whether that motif should appear early in the video.

Do not force it when unnatural.

---

## 11. Editor Handoff

The packet should answer:

- what is fixed
- what is flexible
- which assets already exist
- what the editor must source
- where brand files live
- who resolves questions
- delivery format
- deadline if applicable

---

## 12. Failure Modes

Avoid:

- "use relevant B-roll" as the primary direction
- generic stock footage for abstract narration
- editor being asked to research facts
- graphics without source data
- visuals that imply facts the script does not claim
- over-directing every second
- under-directing essential mechanisms
- unresolved script issues pushed into production
- rights-sensitive assets with no warning

---

## 13. Completion Gate

A video is production ready when a qualified editor can begin work without asking:

> What is this section trying to say?

or:

> What am I supposed to show here?

Creative questions are acceptable.

Editorial ambiguity is not.
